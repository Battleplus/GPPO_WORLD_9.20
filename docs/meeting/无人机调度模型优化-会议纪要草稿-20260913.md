# 《无人机调度模型优化研讨》会议纪要草稿

汇报日期：待核实  
仓库：`WORLD-GPPO_9.11`  
状态：草稿，不自动发送

## 一、会议原意

1. 任务验收语义为“到达指定坐标区域即完成”，需要把物理到达、完成消息和主机确认分开记录。
2. 世界模型应服务于候选 UAV–Task 动作选择，优先预测到达时间、deadline 前到达和执行/能量失败；系统总能耗不是首要动作价值目标。
3. 反事实分支必须共享合法公开历史和外生随机条件，仿真标签不能与模型预测混淆。
4. 世界模型作为 GPPO 先验或辅助评分时，保持环境奖励和安全门禁不变，并与传统调度器、GPPO、GPPO-History 对照。

## 二、当前实际实现

- 旧协议仍是 `continuous_service_until_deadline`；旧结果和负结果保留，不与新协议混合。
- 新增协议 `world-gppo-9.11-arrival/0.1.0`，支持 `arrival_to_region` 和可配置的 `physical_arrival`、`host_confirmation` deadline basis。
- 新语义记录物理到达、完成消息发送和主机合法确认的独立时间；丢失或未确认保持 null。
- 故障、合法动作过滤、通信、ACK、lease、fencing 和能量门禁沿用原实现。
- 旧后果模型的“系统总能耗—残差”路线已封存为负结果；新协议将系统能耗降为辅助指标。
- History 的当前点估计优于 GPPO，但未建立稳定改善证据，且低于传统方法。

## 三、建议的后续工作

1. 先冻结主 deadline basis；在确认前分别报告两种口径，不选择有利结果作为会议验收口径。
2. 使用新到达语义生成按父 episode/前缀分组的反事实数据，保留未到达、拒绝、能量不足和删失样本。
3. 先完成无训练功能验证和合法传统调度器基线，再做单模型、单 seed 的候选后果预测 pilot。
4. 只有预测误差、校准和同状态候选排序均有证据时，才运行 GPPO-History+预测先验；不自动进入大矩阵。

## 四、待确认事项

- 目标区域半径及坐标定义；当前实现默认半径为 0.0，待业务确认后版本化修改。
- 会议主验收 deadline basis：物理到达还是主机确认。
- 完成消息是否由 UAV、任务执行器还是主机网关发送；当前实现把它建模为公共 completion notice。
- “执行失败”是否仅指能量/资源/安全门禁拒绝，还是包括外生故障导致的未到达；当前两者分开记录。
- 汇报日期和参会人名单待核实。

## 五、边界

新协议功能测试通过不等于世界模型改善任务调度；规则基线结果也不等于弱通信可用性通过。旧服务器状态、真实网络流量和历史 raw ledger 仍不补造。
