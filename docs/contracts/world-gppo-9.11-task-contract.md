# WORLD-GPPO_9.11 任务合同与历史差异（draft v0.1.0）

协议版本：`world-gppo-9.11-consequence/0.1.0`  
状态：设计冻结候选，尚未用于新训练。

## 关键决策

首轮继续使用旧项目的持续服务语义，以便把唯一主要变化限制为“候选后果预测”。物理到达指定区域不自动等于任务完成；若会议最终采用“到达即完成”，必须升为新协议版本并重新生成 train/validation/test/OOD tape，完成率不得与旧版本直接比较。

| 语义 | 9.2 历史合同 | 9.11 首轮合同 | 判定/可见性 |
|---|---|---|---|
| 物理到达 | 移动阶段结束 | 记录 arrival event | arrival 不是完成 |
| 服务推进 | 到达后按服务速率累计 | 保留 | 由环境真值推进，策略只见公开遥测 |
| 消息发送 | 通信调度器产生 | 保留 | 记录 sent/dropped/received/expired |
| 主机确认 | ACK/lease/fencing 门禁 | 保留 | 只有合法 ACK、版本、lease 才能执行 |
| deadline | 截止时刻结算 | 保留 | 截止前完成服务才算成功；边界规则写入 tape |
| 能量 | 移动/等待/服务消耗 | 保留 | 低能量拒绝是执行门禁，不泄漏真值 |
| 动作 | 24 个 UAV–Task + NOOP | 保留 | 固定动作空间和 padding mask |
| 任务完成 | 持续服务完成 | 首轮不改 | 到达即完成仅在 v0.2.0+ 单独实验 |

## 可见信息与禁止信息

传统调度器、GPPO、GPPO＋历史、GPPO＋候选后果预测共享同一合法公开观测、动作吞吐、通信、ACK、lease、fencing、能量和安全门禁。隐藏环境真值、未来事件列表、执行器内部状态和反事实分支状态不能进入线上策略。

## 兼容性

本协议不修改旧 checkpoint 的加载格式，也不把新模型 checkpoint 当作旧模型兼容文件。若任务语义、动作空间、归一化或 deadline 规则改变，必须生成新的协议版本、tape、manifest 和独立结果表。
