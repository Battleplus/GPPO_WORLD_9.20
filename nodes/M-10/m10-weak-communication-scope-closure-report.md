## 结论

恢复动作选择补训路线停止。既有开发证据中，“旧策略已经被中断、合法公开候选已经形成、但旧策略没有选择恢复”的数量仍为 **0**；阶段二训练 rollout 没有逐事件 ledger，训练恢复样本数仍未知。因此不能把当前数据改写成 PPO 恢复选择学习问题，也不继续按旧策略失败筛选样本。

当前弱通信能力只能作条件化仿真结论：在单次 damage/disconnect、中断后能合法获知任务状态、公开候选及时形成、且剩余移动/服务时间足够的场景，参考调度器可以恢复服务并完成任务；在高延迟相对有效期、候选不形成或 deadline/物理时间不足的场景，不能宣称可用。小规模边界结果不是生产保证，也不是理论不可行证明。

## 事件分母与完整池结果

四分类的 256 是 episode 级对照，保留原口径：两者成功 172、参考成功/旧策略失败 26、旧策略成功/参考失败 5、两者失败 53。它不能直接作为恢复事件分母，因为部分 episode 的故障没有中断目标任务。

对同一 256 池按“实际中断任务”重算：

| 项目 | 数量 |
|---|---:|
| 真实被中断的事件 | 187 |
| 中断后有合法公开获知 | 187 |
| 获知后出现公开合法候选 | 172 |
| 替代 UAV 产生有效服务 | 170 |
| deadline 前完成严格恢复 | 166 |
| 任务最终完成但不满足严格恢复定义 | 16 |

“任务最终完成但不满足严格恢复定义”包括故障前/非替代路径完成等情形，不能并入恢复成功。严格成功的定义是：任务被中断；控制端通过公开合法消息获知；获知后形成公开候选并接受替代命令；替代 UAV 产生故障后的真实服务；任务在 deadline 前完成；安全拒绝为零。

按严格事件链的失败分类如下：

| 范围类别 | 数量 | 解释 |
|---|---:|---|
| 信息及时且执行机会充分 | 166 | 严格服务恢复并在 deadline 前完成 |
| 信息过期/未形成公开可接管状态 | 15 | 有合法获知时间，但获知后没有公开候选；不是已证实的发布者代码缺陷 |
| 获知时刻已有零时间余量 | 0 | 审计中没有 `deadline_slack_at_knowledge <= 0` 的中断事件 |
| 有信息和候选但时间/物理预算不足 | 5 | 候选存在但未在 deadline 前完成；获知时仍有正 slack，故不能说已证明“获知时零时间” |
| 有信息和候选但未形成有效服务 | 1 | 没有独立 deadline 失败理由的服务缺失 |
| 其他/证据不足 | 0 | 当前事件字段未留下此类未决行 |

因此完整池暴露的主要边界是“公开状态/候选是否及时形成”和随后可用的物理时间，而不是一个已被证明的候选可见策略选择失败。

## 34 条边界扫描

边界扫描只作开发诊断，按真实中断事件计数：29 个中断，其中 27 个严格恢复，1 个信息缺失，1 个获知后候选存在但服务/时间未达成；其余 5 条 episode 未形成真实中断事件，不进入事件恢复分母。

| 因素 | 扫描结果 | 解释 |
|---|---|---|
| 遥测延迟 vs 最大有效年龄 | 中断 4/4 严格恢复；1 条延迟 1.5、max-age 1.0 未形成合法获知 | freshness 越过有效期时，信息路径先失效 |
| 连续失联时长 | 中断 5/5 严格恢复（2.0–6.0 的扫描点） | 在该小扫描配置内，恢复时刻和时间余量仍足够；不外推到更长失联 |
| 获知后 deadline slack | slack 0.212 的点未服务/未完成；2.212、4.212、6.212 点完成 | 该扫描显示时间边界，不证明普适阈值 |
| 替代距离/服务量 | 15/15 严格恢复（距离 0.8–2.4、服务 1.5–3.5） | 仅覆盖该小范围、该任务配置 |
| 并行任务竞争 | 4 条真实中断中参考均未恢复；这些记录含 `no_interrupted_execution` 或无接管服务，不能作为纯策略选择失败 | 需要新的明确定义的并行中断实验才能归因 |

原始 34 条配置、逐行结果和失败理由保存在 `m10-weak-communication-scope-summary-v1.json` 及服务器审计中。没有使用旧策略最终表现来筛选新的最终测试；没有生成新的压力样本。

## 信息、时间和执行障碍的区分

1. **信息路径**：完整池 187/187 个真实中断事件都有合法事件获知记录，但其中 15/187 在获知后没有公开候选。该结果说明当前条件下“任务释放/可接管状态”经常未及时形成；已有观测性审计显示 37/37 stale，静态任务描述缺失 0/37，尚无证据证明必须新增发布者责任或绕过版本/ACK/lease 的实现缺陷。
2. **时间/物理路径**：严格失败中 5 条有候选但未在 deadline 前完成；它们在获知时仍有正 slack，因而只能归为候选形成后剩余移动/服务/执行预算不足或过晚，不得夸大成获知时已经没有时间。边界扫描的 slack=0.212 点同样失败，较大的扫描点成功。
3. **执行路径**：1 条有候选但未形成有效服务；当前没有安全拒绝，不能把它解释成越权门禁误杀。已有并行租约修复及同一执行门禁仍适用；本轮没有修改合同，也没有降低安全门槛。
4. **策略选择**：在 26 条参考成功/旧策略失败中，只有 8 条旧策略自身确实经历目标中断；这 8 条均没有“候选已公开而旧策略未选择”的证据。因此当前数据不能支持“策略不存在任何选择问题”，也不能支持用 A-only 训练解决它。

## 是否实施通信工程改进

本轮不实施新的通信协议改动。现有证据更符合冻结压力条件下的 freshness/时间损失：静态任务信息缺失为 0/37，任务状态和故障路径已有合法消息机制，尚未定位一个可由单项重传或查询改动稳定修复且不改变研究条件的实现错误。

若未来真实通信要求表明需要工程改进，应单独定义版本化的有界任务状态重传/查询协议：请求、回复、重传和 ACK 都经过故障模型；有消息 ID、版本、去重和次数/时限上限；额外字节计入成本；不读隐藏真值、不延长 deadline、不复活旧 lease。该建议不是本轮已验证收益。
